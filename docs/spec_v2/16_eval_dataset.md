# 評価データセットの構築手順（第15部 §7・P0 の詳細化）

> Claude 起草（2026-11-26）。第13部（全体統合・テスト）と第15部（研究知見統合）の「双方向評価データ」を実装可能な手順に落とす。数値はすべて計画値であり、実測値ではない。

## 0. 目的と原則
- 目的：日→ネ／ネ→日の品質を**方向別・カテゴリ別**に測り、重大誤り率（否定・数字・固有名詞・情報の追加/欠落）と人間評価を得る。以後の採否（INT4/INT8、候補多様化、QE、辞書）はこのセットで決める。
- 原則：
  1. 日→ネ用と ネ→日用は**別の原文**から作る（片方の参照訳を逆方向の原文にしない＝翻訳調の原文による過大評価を防ぐ）。
  2. 参照訳は**人が書く／人が確認する**。AI 作成の参照訳は `review_status=UNVERIFIED` のまま採否判断に使わない。
  3. **評価専用**：学習・辞書・プロンプト調整・閾値チューニングに使わない（dev と test を分ける）。
  4. 出典・ライセンス・作成者を行ごとに記録する。

## 1. 規模とカテゴリ（各方向）
| カテゴリ | dev | test | 主な検査対象 |
|---|---:|---:|---|
| 日常会話・挨拶 | 20 | 40 | 自然さ・意味保持 |
| 否定（否定過去・二重否定・部分否定・否定依頼） | 15 | 30 | NEGATION |
| 数字・金額・日時・単位・通貨 | 15 | 30 | NUMBER / CURRENCY |
| 固有名詞（人名・地名・組織） | 10 | 25 | 名前の保持・地名の追加/欠落 |
| 疑問（疑問語・はい/いいえ） | 10 | 20 | WH / QUESTION |
| 依頼・義務・許可・推量 | 10 | 20 | モダリティ |
| 敬語・丁寧さ（तपाईं/तिमी/हजुर） | 10 | 20 | 敬意レベル |

## 2. 原文の集め方（優先順）
1. **ユーザー辞書の会話集**（`dictionaries/phrases.tsv`、公開済み・所有者作成）：原文の候補に使う。ただし辞書に入っている文は**辞書の効果を過大評価する**ため、評価セットに入れた文は「辞書収録」フラグを付け、辞書あり/なしの比較では除外集計も出す。
2. **公的機関の ja/ne 対訳資料**（在ネパール日本国大使館・在日ネパール大使館・在留支援資料など、04a の #14・#16・#17）：利用規約の確認後、文単位で引用（出典 URL・取得日）。
3. **新規作成**：カテゴリの穴埋め。ネイティブまたは作成者が書く。
4. **ASR 由来**：実際の発話（同意を得た録音）を Whisper で文字起こしした結果をそのまま原文にする。音声は保存しない。
- 除外：FLORES-200 等の公開ベンチマーク（モデル学習に混入済みの可能性）、個人情報を含む文、出典不明の文。

## 3. 1行の形式（TSV、UTF-8、NFC）
```
id  direction  category  source  reference  critical_facts  register  origin  in_user_dict  review_status  reviewers  license  notes
```
- `id`：`jn-<cat>-NNN` / `nj-<cat>-NNN`
- `critical_facts`：`|` 区切りの機械検査可能な事実。例 `neg:yes|num:1000|cur:NPR|place:ネパール|wh:price|person:ラム`
- `review_status`：`UNVERIFIED` → `NATIVE_DRAFTED` → `NATIVE_VERIFIED`（2人一致）→ `ADJUDICATED`（不一致を第3者が裁定）／`REJECTED`
- 既存 `tools/eval/testset_seed.tsv` の6列は先頭列互換（追加列は省略可）にし、`run_eval.py` は追加列を読めるよう拡張する。

## 4. 参照訳の作成と確認
1. 参照訳 A：ネイティブ（ne は母語話者、ja は日本語母語話者）が原文だけを見て書く。機械翻訳を見せない。
2. 確認者 B：原文と参照訳 A を見て、意味の一致・数字・否定・敬意を確認。修正案を書く。
3. A と B が一致 → `NATIVE_VERIFIED`。不一致 → 第3者 C が裁定し `ADJUDICATED`、不一致の内容を `notes` に残す（平均しない）。
4. 正解が複数あり得る文は参照訳を複数持てる（`reference` を `||` 区切り）。

## 5. 人間評価（システム出力の採点）
- 盲検：システム名を伏せ、出力の順序を文ごとにシャッフル。同一文の全システム出力を並べて採点（相対比較の安定化）。
- 評価者：各方向 ne 母語話者 2 名以上。
- 採点項目（各文・各出力）：
  - 意味正確さ 0–4（0=逆の意味・別内容、4=完全）
  - **重大誤り**の有無と種類（否定反転／数字・日時・金額の変化／固有名詞の誤り・欠落／原文にない情報の追加／重要情報の欠落／依頼・義務・許可の反転）
  - 自然さ 0–4、敬意の適切さ 0–2
  - 「実際の会話で使えるか」はい／いいえ
- 一致度：重大誤りの有無について評価者間一致（Cohen's κ）を報告。低い場合は基準文書を改訂して再採点。

## 6. 指標と報告
- 方向別・カテゴリ別に：chrF++（参照訳あり）、**重大誤り率（人間）**、**重大誤り検出率（自動 validator の再現率・適合率を人間判定に対して）**、意味正確さ平均、使える率。
- 自動指標（chrF++・将来の QE）と人間評価の相関を方向別に記録（第15部 §4 の採用条件）。
- 採否判定は「重大誤り率が悪化しない」を先に見て、次に意味正確さ。chrF++ だけで採否を決めない。

## 7. 運用
- 保存先：`tools/eval/testsets/`（dev・test を別ファイル）。test は学習・調整に使わない旨を各ファイル冒頭に記載。
- バージョン管理：行の追加・修正は git 履歴で追跡。参照訳の修正は `notes` に理由。
- 秘匿：公開リポジトリのため、個人情報・許諾のない文は入れない。
- 第13部 §シードセット（40文・AI 作成参照訳）は**退行確認用**として残し、採否判断には使わない。

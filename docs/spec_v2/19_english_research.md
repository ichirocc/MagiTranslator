# 英語圏の最新研究の取り込み検討（2026-11-26）

> 第15部の基準で取捨選択。所属は検索結果で確認できた範囲のみ記載（未確認は「所属未確認」）。

## 1. 調べた研究

| 研究 | 内容 | MagiTranslator への示唆 |
|---|---|---|
| **Findings of the WMT25 General MT Shared Task**（Kocmi ほか, WMT 2025, pp.355–413）＋予備順位の報告（arXiv 2508.14909） | 人手評価（ESA／MQM）が正式順位。**自動指標による順位は、QE 再ランキングや MBR を使うシステムに有利に偏りうる**と注意。文書単位の翻訳へ移行 | 自前の候補選択（逆翻訳 chrF＋MBR）で chrF++ が上がっても、**本当の品質向上とは限らない**ことの裏付け。採否は重大誤り率と人手評価で決める方針（第15部・第16部）を維持。chrF++ は退行確認用 |
| **SASST**（arXiv 2508.07781, 2025, 所属未確認） | 凍結した Whisper エンコーダ＋LLM。**構文を考慮したチャンク分割**で、固定の wait-k より適応的に訳を出す | 第17・18部の「節の切れ目で逐次翻訳」を支持。チャンクは文字数でなく構文（節・助詞・接続語）で切る |
| **Koshkin ほか**（arXiv 2603.11578, 2026） | **wait-k は語順の大きく異なる言語対で脆い** | 日⇔ネは同じ SOV なので wait-k 系の破綻は起きにくい見込み（未測定）。それでも固定 k ではなく節単位を採る |
| **SimulS2S-LLM**（arXiv 2504.15509, 2025） | オフライン学習した音声 LLM に、推論時だけ同時通訳の方策（test-time wait-k）を足す | **「オフライン翻訳モデルのまま、推論時の方策だけで同時化する」**考え方は、Madlad を変えずに逐次表示する本アプリの方針と同じ |
| FASST（CMU, arXiv 2408.09430, 2024） | ブロック単位の因果エンコーダで LLM 同時通訳を高速化 | モデル改造が必要なため対象外 |

## 2. 取り入れる設計（第17・18部と統合）
1. **評価**：chrF++ や逆翻訳スコアの上昇を品質向上と見なさない（WMT25 の注意）。採否は重大誤り率・遅延・（後に）人手評価。
2. **逐次表示の方策**：オフラインの Madlad のまま、推論時の方策で同時化する（SimulS2S-LLM と同じ発想）。
   - チャンクは構文で切る（SASST）：ja は「、」「ので」「が」「て」「けど」、ne は र・तर・किनभने・भने 等の節境界。
   - 表示は local agreement（NAIST 2025）：連続する仮訳で一致した先頭だけ確定。
   - 文末（述語）到着後に jane の検査付き最終訳で置換（否定・時制が文末にあるため）。
3. **計測**：遅延（発話終了→仮訳／確定訳）と、確定済み部分の書き換え率。

## 3. 採用しないもの
- 音声 LLM・Whisper＋LLM 統合・ブロック因果エンコーダ等、モデル構造の変更（端末負荷、日⇔ネ非対応）。

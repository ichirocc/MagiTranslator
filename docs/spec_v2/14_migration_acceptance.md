# 3. 移行の原則
1. **旧経路を残す**：`Translator` の既存呼び出し（UI→`Translator`）を、新しい `TranslationEngine` の背後に置く `LegacyTranslatorAdapter` で包む。品質ゲート通過まで削除しない。
2. **一度に1つ**：1 コミット 1 目的。CI が通る単位で進める。
3. **判定を変える変更は分ける**：リファクタ（判定不変、例：IR 化で 130,371 組一致を確認）と、判定を変える改善（例：否定過去の追加）を別コミットにする。
4. **既存設定・資源を壊さない**：SharedPreferences キー、`files/` の資源配置、models-v1 のファイル名を維持する。
5. **番号・型の統一は統合時に行う**：各部の未定義型・重複型（`TranslationCandidate` の二重定義など）は統合版で一本化し、それまで実装は既存クラス名を使う。

# 4. 次に行う移行作業（推奨順）
1. 共通型（`TranslationRequest`/`TranslationResult`/`MagiError`）を Java の不変クラスとして追加し、`Translator` の公開メソッドを薄く包む。
2. validator の `Kind` を `TranslationErrorType`/`IssueSeverity` に写像するアダプター（第5部）。
3. 全候補 hard 時の「要確認」警告を `TranslationResult.warnings` で返し、UI に小さく表示（UI 変更は要承認）。
4. 端到端遅延・メモリの実機計測（第9部・第11部）。
5. 辞書データ基盤の第1歩（第4部 04a §8：許諾表と独自辞書 TSV、`Glossary`/`Places` の外部化）。
6. ネイティブ評価（第13部 §6）。

# 5. ユーザー（オーナー）にしかできない作業
| 作業 | 理由 |
|---|---|
| プライバシーポリシーの運営者名・連絡先、同意リンクの差し替え | 推測で埋めない |
| 署名鍵の生成と CI secret 登録（他者配布前） | 秘密情報 |
| データ源のライセンス「要確認」欄の確定（04a） | 規約の解釈と責任 |
| Whisper_ne のライセンス・帰属確認 | 同上 |
| ネイティブ評価者の手配 | 人手 |
| 実機での初回ダウンロード・会話テスト | 端末が必要 |

# 6. 最終受入基準（リリース判定）

次の**すべて**を満たした版を「完成」とする。1つでも欠ければ完成と報告しない（第3部 §22.6）。

## 6.1 機能
1. 新品の Pixel 10 Pro XL に APK を入れ、資源を導入し、ja⇔ne・ja⇔vi のテキスト・音声翻訳ができる。
2. WalkieTalkie で ja⇔ne 会話が成立する（第9部 §12）。
3. オフライン（機内モード）で全機能が動く（資源導入後）。

## 6.2 品質
4. 方向別の最終テストセットとネイティブ評価で、raw Madlad に対する jane の優劣が**方向別に**記録されている。劣る方向がある場合は、その方向で jane を無効化するか、劣る理由と対策を記録している。
5. 重大誤訳（否定逆転・数値・固有名詞・義務/禁止）の発生率が記録され、旧版より悪化していない。
6. ASR の WER/CER が方向・モデル別に記録されている。

## 6.3 安定性・性能
7. 30 分連続使用で異常終了なし。
8. p50/p95 遅延・ピークメモリ・発熱時の挙動が記録されている。

## 6.4 安全・プライバシー
9. release ログに本文が出ない。
10. 会話内容が既定で永続化されない。
11. 外部送信がない（オンライン既定 OFF、STRICT_LOCAL）。
12. 資源は SHA-256 検証済み（署名を有効化した場合は署名も）。
13. 他者に配布する場合：署名鍵差し替え済み、プライバシーポリシー確定済み、同梱データのライセンス表示あり。

## 6.5 文書
14. 統合仕様書（本 v2 を一本化したもの）が最新で、実装状態（実装済/部分/未実装）と一致している。
15. すべての品質主張が `docs/eval/` の記録に紐づいている。

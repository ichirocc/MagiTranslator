# 0. 目的
各部の機能を統合したうえで、**品質・安定性・プライバシーを測定可能な形で確認**する。実測のない改善主張を禁止する（D9）。

# 2. 評価データ

## 2.1 シードセットの限界（重要）
- `tools/eval/testset_seed.tsv`：40 行（ja→ne 20、ne→ja 20）。
- **参照訳は AI 作成で未検証**（ファイル冒頭に明記）。よって chrF++ の数値は「同じ参照に対する相対比較」にしか使えず、**品質の絶対値や市販ソフトとの比較の根拠にならない**。
- 行数が少ないため、1 行の変化で指標が数ポイント動く。差が小さい比較は結論を出さない。

# 6. ネイティブ評価プロトコル

## 6.1 評価者
- ネパール語の母語話者で日本語を業務レベルで理解する人を最低2名。日本語母語話者1名（ne→ja の自然さ）。
- 利害関係の記録。評価者 ID は匿名化。

## 6.2 手順
1. 評価対象（原文・候補）をシャッフルし、**生成元（raw / jane / 他モデル）を隠す**。
2. 各文について第3部 §19.4 の 10 項目を、0〜3 の4段階＋重大誤訳フラグ（否定逆転・数値・固有名詞・人物・義務/禁止）で採点する。
3. 参照訳の修正案を記入してもらい、シードセットの `review_status` を `native_reviewed` に更新する。
4. 評価者間の不一致は平均せず、基準の曖昧さとして議論・記録する（§19.4）。
5. 結果は `docs/eval/native/` に保存（評価者の個人情報は含めない）。

## 6.3 最小規模
- 最初の1回：シードセット 40 行×4 系統（raw Madlad / jane v4 / 必要なら他）。
- 結論を出す規模：方向別 200 文以上（目安。実施後に見直し）。

# 7. 回帰監視
- CI の L1〜L3 を全 push で実行【実装済】。
- 翻訳出力の回帰（L4）は手動実行で、結果を `docs/eval/outputs/` に日付付きで保存【実装済】。
- 【未実装】L4 の小規模版（数文・机上見積りで CI 時間内）を CI に入れるかは、モデルのダウンロード時間・容量を見積もってから判断。

# 8. 受入条件
1. L1〜L3 が CI で常時成功。
2. 方向別の開発・最終テストセットがあり、最終テストを調整に使っていない。
3. ネイティブ評価を少なくとも1回実施し、参照訳が検証済みになっている。
4. 品質の主張はすべて `docs/eval/` の記録に紐づいている。
5. 実機テスト（L6）が記録されている。

# 9. 実装AIへの指示
- 参照未検証のシードセットの数値で「改善した」「市販を超えた」と書かない。
- 評価の前後比較は同一データ・同一後処理で行う。
- 評価データに個人情報を入れない。
- CPU 負荷の大きい評価は、行数×候補数×デコード回数から時間を見積もってから実行する。
